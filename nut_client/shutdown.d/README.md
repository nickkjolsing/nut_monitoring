# shutdown.d — per-client shutdown drivers & hooks

`poweroff.sh` (generated by [entrypoint.sh](../entrypoint.sh)) is a thin
orchestrator: it owns the shared logic (`DRY_RUN`, `SHUTDOWN_GRACE`, logging)
and delegates the *actual* halt to a **driver** picked by `SHUTDOWN_PROFILE`.
Around the halt it runs optional **hooks** for quiescing the host.

This directory is baked into the image at `/etc/nut/shutdown.d`. To customize a
client you can either edit these files and rebuild (`docker compose up -d
--build`), or bind-mount your own dir over it (see
[docker-compose.yaml](../docker-compose.yaml)).

## Flow

```
poweroff.sh
  ├─ DRY_RUN=true?            → log "would power off" and exit (nothing below runs)
  ├─ sleep SHUTDOWN_GRACE     → abort window before anything destructive
  ├─ pre.sh   (if present)    → quiesce: stop VMs/jails/containers, sync, unmount
  ├─ do_shutdown "$reason"    → the halt (default, or from <profile>.sh)
  └─ post.sh  (if present)    → runs after the halt returns (remote drivers)
```

## Drivers — `<profile>.sh`

A driver is a POSIX-sh file that defines a `do_shutdown` function. It is
**sourced** by `poweroff.sh`, so it sees all the client's env vars and can use
`/etc/nut/nutlog <level> <event> <msg> [k=v ...]` for logfmt logging.

```sh
# /etc/nut/shutdown.d/myprofile.sh
do_shutdown() {
  reason="$1"
  nsenter -t 1 -m -u -i -n -p -- /sbin/poweroff
}
```

Select it with `SHUTDOWN_PROFILE=myprofile` in `.env`. The built-in `default`
profile needs no file — it `nsenter`s into pid 1 and runs `/sbin/shutdown -h
now`. If a named profile's file is missing, the orchestrator falls back to the
default halt (better to power off than hang on battery).

> Halting the host from inside the container needs `pid: host` + `privileged`
> (already set in docker-compose). Remote drivers (e.g. `ssh`) don't.

## Hooks

- **`pre.sh`** — runs before the halt to quiesce the host. This is usually where
  the NAS-specific "shut down in a specific way" work goes. Gets `REASON` in env.
- **`post.sh`** — runs after `do_shutdown` returns. Only meaningful for drivers
  that don't actually halt this host (e.g. remote/ssh). Gets `REASON` and `RC`.

Both are optional and run only if the file exists. Copy a `*.example` to the
real name to enable it.

## Bundled examples

| File             | `SHUTDOWN_PROFILE` | What it does |
|------------------|--------------------|--------------|
| `systemd.sh`     | `systemd`          | `nsenter` → `systemctl poweroff` |
| `truenas.sh`     | `truenas`          | `nsenter` → `/sbin/shutdown -p now` (clean power-off) |
| `hexos.sh`       | `hexos`            | Same halt as `truenas` (HexOS is TrueNAS SCALE-based); see file for Docker-app quiescing notes |
| `ssh.sh`         | `ssh`              | Remote shutdown over SSH (for appliances that can't run this container) |
| `pre.sh.example` | —                  | Sample quiesce hook (stop Docker containers, `sync`) |
